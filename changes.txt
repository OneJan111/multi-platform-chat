================================================================================

CHANGE SUMMARY: Remove unnecessary full-page refresh in multi-platform-chat-main

Target file: app.py   (Streamlit app)

================================================================================

 

CONTEXT / WHY

--------------------------------------------------------------------------------

This is a Streamlit dashboard. It refreshed the ENTIRE page every

CHAT_POLL_INTERVAL seconds (default 5s) by running st.rerun() from a timer

fragment. That re-executed the whole ~3500-line script on every tick: the big

CSS block, the module reload checks, and ALL SIX tabs (Chat, Stream Monitoring,

OBS, Analytics, Filters, Cookies) -- even though the only thing that needs to

update on a tick is the chat feeds.

 

The idiomatic Streamlit fix is to NOT call st.rerun() for the whole app, and

instead put only the live content inside its own `@st.fragment(run_every=...)`.

That way only the chat feed re-renders each tick; the rest of the page and the

other tabs are untouched, and button clicks / typing elsewhere are never

swallowed by a server-side sleep.

 

The overlay page in the same file already used the correct pattern

(`@st.fragment(run_every=2)`), so this change just brings the main dashboard

in line with it.

Inside `with tab_chat:`, AFTER the interactive controls (the "Send to" targets

row, the site-emote row, the send form `st.form("send_form")`, the

    final "Auto-refreshes every ... messages shown" markdown goes inside the

    `_feed_renderers` dict, the `feeds_box` container loop, and the auto-refresh

BEHAVIOR NOTE / FOLLOW-UP

--------------------------------------------------------------------------------

Before this change, the Analytics and Stream Monitoring tabs received fresh

poll data "for free" on every 5s full rerun. After the change, polling lives in

the Chat tab fragment, so those tabs refresh only when you interact with them or

switch to them. For a dashboard this is usually fine. If live ticking is wanted

there too, give those tabs their own `@st.fragment(run_every=...)` wrappers.

 

The original reason for using a run_every fragment instead of time.sleep()

(avoid swallowing button clicks during a server sleep) is preserved -- the fix

only narrows the rerun scope from the whole app to the chat feed.
